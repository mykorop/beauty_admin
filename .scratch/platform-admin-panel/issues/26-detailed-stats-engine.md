# 26: Детальна статистика: рушій + ріст, Записи, Вартість Записів

**What to build:** Адміністратор платформи натискає «Порахувати», бачить перебіг і отримує графіки росту, Записів і Вартості Записів із живих даних (ADR-0003).

**Blocked by:** 25 (Дашборд: Базові показники)

**Status:** ready-for-agent

Специфікація: `../spec.md` · Словник: `CONTEXT.md` · ADR: `docs/adr/`. Тикет зачіпає обидва репозиторії (`bookme-backend` → `admin-api`, `beauty_admin` → UI), якщо не сказано інше.

- [ ] `POST /admin/stats/detailed` запускає обчислення асинхронно й повертає його ідентифікатор; `GET` повертає стан і останній результат із часом побудови; одночасно — не більше одного обчислення
- [ ] Обчислення сканує таблицю посторінково й агрегує в пам'яті; результат зберігається одним рядком конфігурації до наступного запуску
- [ ] Агрегація — чистий модуль (потік рядків + «зараз» + часовий пояс → статистика), який не знає про DynamoDB
- [ ] Ріст: нові Салони, Майстри, Клієнти по днях і тижнях
- [ ] Записи по днях за статусами, частка скасувань; минулі «заброньовано» — окрема категорія
- [ ] Вартість Записів у MDL за поточним курсом наявного сервісу курсів: без скасованих і «не з'явився»; окремо минула й заброньована наперед; підпис у UI, що це не виручка
- [ ] День — за `Europe/Chisinau`
- [ ] Юніт-тести модуля: межі дня, перехід на літній час, змішані валюти, виключення статусів, порожня таблиця
- [ ] UI: кнопка запуску, перебіг, час останнього результату, три графіки; Playwright на запуск і опитування
